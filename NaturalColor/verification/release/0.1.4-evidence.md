## Photographic changes

This beta incorporates the Round 4 scene-tone stage in front of the preferred
recovered colour/Standard renderer: retained RAW highlight headroom, a smooth
highlight shoulder, limited backlit shadow fill, and P3 output without early sRGB
clipping. Quiet scenes retain the original operator. RAW exposure placement stays
unchanged pending grey-card calibration. High-contrast HEIC can carry an ISO HDR
gain map on iOS 26+; JPEG and older OS exports remain SDR.

The export keeps its HDR graph lazy and explicitly declares SDR/HDR content
headroom. It does not add a separate full-resolution floating-point raster.
Rendering provenance identifies build, input/development and output settings.
Save RAW original retains its existing retention-only behaviour on ProRAW cameras.

## Why the earlier HDR test failed

The iOS Simulator decodes the gain-map HEIC as SDR, including when its auxiliary
map is explicitly applied. This initially looked like an encoder failure.
[Independent native macOS decoding](https://github.com/normiecore/dashcam-claude/actions/runs/39207515652)
of the **actual app HEIC** from run 39206541891 restored headroom 4 and linear
ladder values approximately [0.287, 1.040, 2.310, 3.998]; maximum error from the
expected HDR ladder was 0.0054. The file was valid. Synthetic writer matrices also
restored the expected HDR range across the tested APIs.

The final verification therefore preserves simulator assertions for the real
float renderer, SDR base, map presence and provenance, exports the actual HEICs
as XCTest attachments, and mandates native macOS readback of both the numerical
ladder and a full 8064 x 6048 public-RAW export. The host check verifies accurate
HDR values, explicit gain-map agreement, dimensions, map presence and a real HDR
pixel peak. Physical-device targets retain their local HDR expansion assertions.
