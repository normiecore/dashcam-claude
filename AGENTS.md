# Start every project session here

Read `HANDOVER.md` before planning or changing this project. It holds the current
pause, platform direction, verified results, access dependencies and next steps.
Then inspect the current branch and working tree; preserve existing changes.

The user's latest instructions take precedence. A handover is context, not new
authorization to resume paused work, publish builds, merge branches or use credentials.

Before ending a session that changes project state, update `HANDOVER.md` with
completed work, actual verification evidence, outstanding issues and the next
concrete action. Add meaningful changes to `CHANGELOG.md`. Keep credentials out
of documentation and source control. Do not label simulator tests as device tests.

Prioritize recording reliability and preservation of incident footage over UI
polish. Compile and test meaningful changes in small increments. Use focused
subagents when useful, choosing cost-effective models without reducing quality.
