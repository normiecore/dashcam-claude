# 0.1.2 assessment and rendering decision

A private supplied test set contained 55 originals: 15 DNGs, 31 JPEGs and 9 HEICs. Actual 48 MP sensor decoding succeeded on the late 94.9 MB RAW. No private images, filenames, Drive references, contacts or location metadata are included here.

RAW files ranged from 52.4–94.9 MB (65.4 MB median), confirming the need to avoid requesting RAW unless selected. Processed JPEGs had a 6.8 MB median; native HEICs had a 2.3 MB median, but different resolutions/scenes mean these numbers are not a valid codec-efficiency comparison.

Visual review found useful detail and restrained colour, with heavier shadows in several processed indoor/late-light examples and a sideways image inside a portrait output. Selected original-pixel texture checks did not justify a blanket sharpness, saturation or white-balance change. The candidate keeps Apple RAW development defaults instead of forcing tone/gamut controls off, follows held-device orientation, and applies an independently authored subtle luminance finish. New output still needs physical-iPhone review; no calibrated colour accuracy is claimed.

The analytic finish uses standard Rec.709 luminance weights in linear sRGB. Its neutral curve is y + 0.08*y*(1-y)*(1-2*y), fixing black, middle grey and white with a derivative of at least 0.96 over [0,1]. A shared RGB multiplier preserves linear-light chromaticity; a headroom guard avoids lifting an existing unit peak. Extended-gamut channels are not pre-clamped to sRGB. HEIC exports are tagged Display P3; compatible JPEG is sRGB. This is SDR output.

Archived recovered C++/Metal implementations, tables and profiles remain in repository history/research for provenance, but are excluded from the shipping target. The production bundle audit rejects those resource files. New rendering tests check independent invariants; the old renderer’s golden tests are archived and do not specify this different implementation.

Hosted verification covers public RAW sensor decode/full-size export, supported native export codec/dimensions, compression presets, crop dimensions, rotation mapping, neutral/chromaticity invariants, import errors, UI routes and the production archive. It cannot prove physical capture orientation, Photos transactions, camera performance, or that the new rendering matches the private photographs. See the store release checklist for phone acceptance.
